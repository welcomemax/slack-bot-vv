# Slack-бот общего заказа во ВкусВилле

Бот по команде `/vv` публикует акции на готовую еду и собирает общий заказ кнопками. Корзину он не оформляет и не оплачивает: организатор получает ссылку `share_basket` и проверяет цены и наличие сам.

Ручной сценарий в том же канале не меняется. Бот не читает обычные сообщения, не ставит реакции на ответы людей и не забирает `:heavy_plus_sign:` / `:heavy_check_mark:`. `:white_check_mark:` появляется только на посте `/vv`, когда организатор нажимает «Заказ оформлен».

## Запуск

Нужен Node.js 24.

```bash
npm i
cp .env.example .env
npm run dev
```

`npm run dev` — `tsx watch --env-file=.env src/app.ts`.  
`npm start` — `tsx --env-file=.env src/app.ts`.  
`npm test` — `tsx --test tests/*.test.ts`.

Каталог `tsx --test tests/` в tsx 4 не работает: аргумент-папка воспринимается как импорт модуля. Скрипт поэтому передаёт файлы `tests/*.test.ts`.

В `.env`:

| Переменная | Зачем |
|---|---|
| `SLACK_BOT_TOKEN` | Bot token, `xoxb-` |
| `SLACK_APP_TOKEN` | App-level token с scope `connections:write`, `xapp-` |
| `ALLOWED_CHANNELS` | Id каналов через запятую. В остальных бот отказывается |
| `VV_MCP_URL` | По умолчанию `https://mcp.vkusvill.ru/mcp` |
| `VV_USER_AGENT` | Честный User-Agent, не браузерный |
| `TZ` | `Europe/Moscow`, по ней считается «сегодня» |
| `DISCOUNT_CACHE_MIN` | Кеш акций, 30 минут |
| `SEARCH_CACHE_MIN` | Кеш поиска, 10 минут |
| `TOP_DISCOUNTS` | Сколько блюд в посте, 12 |
| `DB_PATH` | SQLite, `data/orders.db` |
| `ORDER_RETENTION_DAYS` | Заказы старше этого срока удаляются, 7 |

Секреты только в `.env` или в секрет-хранилище. `.env` в `.gitignore`. В логах нет токенов: при ошибке ВкусВилла пишутся статус и support id, если он есть в теле ответа.

## Slack-приложение

1. [api.slack.com/apps](https://api.slack.com/apps) → Create New App → From a manifest. Вставь `slack-manifest.yml`.
2. Включи Socket Mode, если манифест ещё не включил. App-level token: Basic Information → App-Level Tokens → scope `connections:write`. Это `SLACK_APP_TOKEN`.
3. Install to Workspace. Bot User OAuth Token — это `SLACK_BOT_TOKEN`.
4. Пригласи бота в тестовый канал и впиши id канала в `ALLOWED_CHANNELS`.
5. `npm run dev`. В логе должно быть `socket mode started`. Не должно быть `Failed to send ping` и `pong wasn't received` хотя бы 10 минут. Проверь `/vv`, кнопку «Хочу» и упоминание.

Скоупы v1: `chat:write`, `commands`, `app_mentions:read`, `reactions:write`. Публичный URL не нужен.

Для v2 (разбор строк «название цена» из треда) понадобятся `message.channels` и `channels:history`, для приватного канала ещё `groups:history`. Тогда бот будет получать все сообщения канала: в коде их нужно фильтровать и не писать лишнее в базу и логи. В v1 этих подписок нет.

## Как пользоваться

1. Кто первым вызвал `/vv` сегодня в этом канале, тот организатор. Бот пишет «вкусвилл :cherries:» и акции на готовую еду: название со ссылкой, старая и новая цена, скидка, срок, кнопка «Хочу». Сверху — «Цены общие, в приложении может быть дешевле». Если акций нет, так и написано.
2. «Хочу» добавляет блюдо. «Мой заказ» — личное сообщение со «Убрать» и «+1». В треде одна сводка, она обновляется. Людей бот не тегает.
3. «Собрать корзину» доступна только организатору. Одинаковые позиции склеиваются, пачки по 20 уходят в `vkusvill_cart_link_create`. В тред приходят ссылки и текст «Корзина готова, проверь цены и наличие и оформи сам». Ссылку можно открыть и ничего не оформлять.
4. «Заказ оформлен» закрывает приём и ставит `:white_check_mark:` на пост.
5. `@вкусвилл карбонара` — до трёх вариантов готовой еды в треде, у каждого «Хочу».

Повторный `/vv` в тот же день не меняет организатора и обновляет список акций. После «Заказ оформлен» новый заказ в этом канале откроется уже на следующий день.

Кнопки «Хочу» помнят блюда, пока процесс жив. После перезапуска старый пост их уже не узнает: вызови `/vv` ещё раз или напиши боту название.

## Откуда данные

Официальный MCP `https://mcp.vkusvill.ru/mcp`, протокол `2025-03-26`, Streamable HTTP. Сервер без сессии: `Mcp-Session-Id` не присылает. Ответ инструмента — JSON-строка в `content[0].text`.

Готовая еда — товар, в цепочке `category[]` которого есть `id: 50361`. Параметр `category_id` у поиска для этого id не используется. Акции: все страницы `vkusvill_products_discount` для `card` и `quantity` с `vvonly: 1` (так у инструмента по умолчанию, 09.10.2026 это 12 + 2 страницы, около 14 запросов). `vvonly: 0` — это уже сотни страниц и упирается в лимит 60 запросов в минуту на IP, поэтому v1 его не включает.

Перед сервером стоит QRATOR. User-Agent берётся из `VV_USER_AGENT` и кладётся в `requestInit.headers` транспорта. 403 не повторяется: support id пишется в лог, в канал уходит «ВкусВилл заблокировал запрос. Попробуй позже.» 429 и 5xx — пауза и ещё две попытки, потом «ВкусВилл сейчас не отвечает, попробуй позже» или «ВкусВилл сейчас занят, попробуй через минуту».

Кеш в памяти процесса: акции 30 минут, поиск 10 минут.

### Цены

09.10.2026 у `data.meta` скидок `personalized: false`. На скриншотах организатора в тот день цена была ниже, чем в MCP (пример: 216 ₽ на скриншоте и 260 ₽ в ответе инструмента). Бот показывает общую цену из MCP и прямо пишет, что в приложении может быть дешевле. Наличия без OAuth нет, бот его не обещает.

OAuth ВкусВилла в этой версии нет: ни полей, ни таблиц под токены.

## База

SQLite через `node:sqlite`. В заказе дня: id канала, день, организатор, id пользователя Slack, `xml_id`, название, цена, количество, `ts` поста и сводки. При старте и раз в сутки удаляется всё старше 7 дней.

## Тесты

```bash
npm test
LIVE_MCP=1 npx tsx --test tests/contract.test.ts
```

Обычный прогон на фикстурах: фильтр 50361, нормализация, нарезка корзины по 20, экранирование `<!channel>` и `<@U1>`, лимит Block Kit, сообщения для 403/429/5xx. Контрактный тест ходит в живой MCP и проверяет, что нужные tools на месте и у скидки у товаров есть `category`.

## Bun

Не используем, пока не закрыт [oven-sh/bun#37110](https://github.com/oven-sh/bun/issues/37110): `@slack/socket-mode` 3.x шлёт ping через `undici`, в Bun его нет, и Socket Mode переподключается по кругу.

## Не в этой версии

Разбор строк «название цена» из треда, замены через `product_analogs`, утренний пост по расписанию, картинки товаров, поиск вроде «что-то лёгкое до 300». Фильтр готовой еды и поиск оставлены отдельными функциями, чтобы это можно было добавить, не переписывая заказ.
